# Motorcycle catalogue and photo API research

Checked **3 November 2026**. Recommendation: expand the curated model vocabulary independently from photo availability, and keep Commons-based, locally hosted reference photos for the MVP. Show a photo only after verifying its model and exact year, or a documented generation range. An API accepting a `year` parameter does not establish that its returned picture matches that year.

This review used providers' own documentation, pricing, and terms. Coverage totals below are vendor claims, not an independently tested inventory. No accounts, paid trials, credentialed API requests, or vendor contacts were used.

## Coverage and accuracy limits

API Ninjas' published examples include Japanese and European manufacturers and mention `cfmoto` search normalization, but do not establish image coverage for particular Chinese model-years. CarImages shows Japanese/European examples, while Data and APIs publishes broad brand totals. None of those totals proves coverage of the motorcycles actually used in Kazakhstan, domestic-market variants, or older imports. **Kazakhstan/Chinese model-year photo coverage remains an evaluation question**, not a verified purchasing claim. [API Ninjas](https://api-ninjas.com/api/motorcycles), [CarImages](https://carimagesapi.com/motos), [Data and APIs](https://dataandapis.com/apis/motorcycles)

Keep specifications and imagery separate. For example, the official NHTSA vPIC API can return motorcycle makes/models by year and vehicle type; that published catalogue functionality is not a photo service. Similarly, a vendor's number of specification records should not be presented as its number of verified photographs. [vPIC API](https://vpic.nhtsa.dot.gov/api/)

## Workable MVP path

1. Expand canonical make/model names and Latin/Cyrillic aliases first; preserve freeform entries. A model can be selectable while `images` is empty.
2. Continue offline Commons ingestion using `action=query`, `prop=imageinfo`, and `iiprop=url|size|extmetadata`, requesting a suitable thumbnail width. Save source description evidence, attribution, license URL, dimensions, and the verified year/range beside the local asset. Metadata is HTML-formatted and should be handled as source data, not injected into the app. Request a few `extmetadata` records at a time. [Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo)
3. Verify model identity and year from the source description or stronger manufacturer evidence. A photograph's capture/upload date is not a model-year certificate. Do not extend one verified year to a whole generation by visual guesswork. These are our curation rules, not guarantees supplied by an API.
4. If manual sourcing becomes the bottleneck, evaluate CarImages and Data and APIs against a fixed list of actual pilot bikes: exact variant/year, real photo versus render, no nearest-year fallback, missing-image behavior, and written self-hosting/termination rights. Keep provider-dependent images separate from permanently licensed local assets.

Generated illustrations may be useful as clearly labelled artwork elsewhere. They do not authenticate a motorcycle's model-year identity and should not enter the verified reference-photo catalogue. For an unmatched model/year, retain **no image** rather than synthesizing a purported photograph.
